## Why the new modules exist

A persona saying “I am rational” is not a game-theoretic model. A payoff table
makes the assumed incentives explicit. Computing best responses identifies which
action maximizes a player's expected utility under supplied beliefs. Regret is
the utility forgone by a worse action. A pure Nash profile means no player can
improve by changing only its own action. It does not predict which equilibrium
people select, or assert rationality/complete information in the actual world.

A message reaching someone is not proof that it changed their action. The new
social experiment removes selected directed links while keeping world resources,
events and role descriptions fixed. It then asks fresh roles in both worlds.
That yields an inspectable model experiment; it does not identify human causality.
Removing a link can also change feed competition for attention, not just hide
one post. All failed/incomplete arms remain explicit in denominators.

Probability arithmetic and Bayesian reasoning, when supplied with beliefs and
likelihoods, are different from obtaining trustworthy inputs. Provider confidence,
observed turnover and a well-written persona do not supply real-world event odds.
Forecast scoring only helps once timestamped predictions have resolved outcomes.

## Offline strategic demo

```sh
uv run --project engine decision-lab mechanics game \
  --input engine/examples/launch-coordination.game.json \
  --output engine/output/my-coordination-analysis.json
```

The two-player example uses assumed utility points for a hypothetical operator
and liquidity partner. It has two pure Nash profiles: review+escrow participation,
and skip-review+wait. These are conditional solutions of the table, not proposed
real trades. Beliefs are explicit basis-point distributions; no default uniform
prior is invented. Expected utility/regret is exported as exact rational numbers.

Bounds: 2–4 players, 2–8 actions per player, at most 256 complete action profiles. The
module solves pure Nash and pure-action strict dominance only. Utility provenance
is retained; utility points do not become ledger cash. Analysis makes no model or
network request and the CLI refuses to overwrite an artifact.

## Explicit Bayesian reasoning demo

```sh
uv run --project engine decision-lab mechanics bayes \
  --input engine/examples/event-belief-update.json \
  --output engine/output/my-belief-update.json
```

The example starts with an assumed 40% attention-persistence prior and two
illustrative evidence likelihoods. Exact posterior arithmetic gives 4/5 (80%).
This is a teaching result conditional on those invented assumptions, **not an
80% forecast for a real coin or political event**. Every likelihood retains its
provenance; we do not infer it from a headline or Jev's confidence.

The kernel assumes a finite mutually exclusive/exhaustive hypothesis partition
and signals conditionally independent given the hypothesis. Repeated copies of
the same news are not independent evidence. It rejects impossible evidence with
zero total likelihood, keeps zero priors at zero and emits exact ratios rather
than rounding probabilities into a false precision claim. Bounds: 2–16 hypotheses,
0–8 signals. No evidence leaves the prior unchanged. A posterior is only as useful
as the hypotheses, prior and likelihood model; the code cannot verify those
scientific assumptions automatically.

```sh
uv run --project engine decision-lab social prepare \
  --input engine/examples/social-information-experiment.json \
  --output engine/output/my-social-plan.json

uv run --project engine decision-lab social inspect \

The bundled explicit example has three actors, two interaction rounds, two arms

  --input engine/examples/social-information-experiment.json \
  --output-dir engine/output/my-social-experiment \
  --max-calls 24 --transport agy --model gemini-3.8-flash-high \
  --timeout 180 --public-input --allow-model
```

Do not put confidential scenarios through that development CLI. Native endpoints
and Jev actor inference are supported explicitly; see [Jev setup](JEV_INTEGRATION.md).
Each arm's `result.json` contains observations/actions and reproduces through
`agents replay`. The root `analysis.json` reports completed/excluded pairs and
exact per-pair plus mean/median/min/max metric differences. The root manifest's
completed-call counts update after each arm; inspect the active arm manifest for
in-flight calls. Maximum matrix: 256 calls, 1–4 seeds. No retries or hidden provider
fallback occur. Output/model limits may stop an arm; it is not counted successful.

## Decision on remaining scope

These are composable implementations, not a promise of a single universal solver.
Authoring still sits outside the pure engine: users and their chosen agent must
supply and review resources, utilities, likelihoods, actions and information rules.
Automatic game creation with verified payoff evidence, strategy learning,
endogenous paid campaigns/founder financial choices and empirical calibration
remain work. We should add one mechanism with a testable use case at a time.
